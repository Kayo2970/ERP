1

What you'll need first

  • A fresh VPS running Ubuntu 22.04 or 24.04 LTS (these commands are for Ubuntu/Debian — apt-based). 2 vCPU / 4 GB RAM is comfortable for this app.
  • Root or sudo SSH access to it, and its public IP address.
  • A domain name you control, with access to its DNS (e.g. Hostinger hPanel, as used for the mail-authentication setup).
  • Access to the GitHub repository — https://github.com/Kayo2970/ERP — either as a public clone or with a Personal Access Token if it's private.
  • A terminal with SSH (Terminal on Mac/Linux, or PuTTY/Windows Terminal on Windows).
2

Point your domain at the VPS

In your DNS provider's zone editor, add (or update) an A record pointing your domain at the VPS's IP address:

TypeNameValue
A@YOUR_VPS_IP
AwwwYOUR_VPS_IP

DNS can take anywhere from a few minutes to a few hours to propagate. You can start the server setup below while you wait — you'll just need propagation to finish before the HTTPS step (Step 12).

If you'll also be sending mail from this box (Direct Send SMTP, DKIM, SPF, DMARC, BIMI), that's a separate set of DNS records covered in full in docs/direct-send-setup-guide.html in this same repo — do this domain-pointing step first, then follow that guide for mail once the app is live.
3

First login & basic server lockdown

SSH in as root the first time, update the system, then create a dedicated non-root user to run everything as:

ssh root@YOUR_VPS_IP

apt update && apt upgrade -y

adduser deploy
usermod -aG sudo deploy

Log out, then log back in as deploy for everything from here on — running the app as root is unnecessary risk.

ssh deploy@YOUR_VPS_IP

Install a basic firewall and only allow SSH for now (you'll open HTTP/HTTPS in Step 13, once Nginx is actually running):

sudo apt install -y ufw
sudo ufw allow OpenSSH
sudo ufw enable
Confirm ufw status shows OpenSSH: ALLOW before you close your current SSH session — locking yourself out of a fresh VPS is a real (and annoying) way to lose an afternoon.
4

Install Node.js 22 LTS

This app is built on Next.js 16 + React 19, which needs a current Node — 22 LTS is the safe choice. Install it via NodeSource:

curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

node -v
npm -v

node -v should print something like v22.x.x.

5

Install PM2 & Nginx

PM2 keeps the Next.js server running in the background, restarts it if it crashes, and brings it back up automatically after a reboot. Nginx sits in front of it as the public-facing web server, handling HTTPS and proxying real traffic through to the app on its internal port.

sudo npm install -g pm2
sudo apt install -y nginx

pm2 -v
nginx -v
6

Clone the repository

Install Git and clone the repo into /var/www:

sudo apt install -y git
sudo mkdir -p /var/www
sudo chown deploy:deploy /var/www

cd /var/www
git clone https://github.com/Kayo2970/ERP.git leads-erp
cd leads-erp/leads-dashboard

The Next.js app itself lives in the leads-dashboard subfolder of the repo — every command from here on runs from inside that folder.

If the repository is private, cloning over plain HTTPS will prompt for credentials that don't work with a GitHub password anymore. Either clone with a Personal Access Token in place of the password, or set up an SSH deploy key and use git clone git@github.com:Kayo2970/ERP.git leads-erp instead.
7

Install dependencies

From inside leads-dashboard:

npm install

This pulls in everything the app needs, including the built-in OCR engine (Tesseract), PDF rendering, and the direct-send mail engine — no extra system packages required for any of those.

8

Configure environment variables

Copy the example file and fill it in:

cp .env.example .env
nano .env
VariableWhat it's for
DATA_ENCRYPTION_KEYEncrypts every server data file at rest (members, events, tasks, everything under data/). Not required to boot — falls back to a built-in default — but that default is baked into the public source, so treat this as required for any real deployment.
SMTP_HOST / SMTP_PORTFallback mail relay target (defaults to localhost:25, i.e. a local Postfix relay). Only matters if you pick the "Local Postfix" provider in the dashboard's Email settings later — the built-in Direct Send engine doesn't use these.
ANNOUNCEMENT_FROM_EMAILDefault "from" address used until you configure real SMTP credentials in the dashboard.
ANNOUNCEMENT_FROM_NAMEDefault sender display name — normally fine left as LEADS Next Gen Centre.

Generate a strong, random encryption key rather than typing one by hand:

openssl rand -hex 32

Paste the output as DATA_ENCRYPTION_KEY= in .env. Your file should end up looking roughly like:

DATA_ENCRYPTION_KEY=paste the openssl output here
SMTP_HOST=localhost
SMTP_PORT=25
ANNOUNCEMENT_FROM_EMAIL=leads@yourdomain.com
ANNOUNCEMENT_FROM_NAME=LEADS Next Gen Centre
Back up DATA_ENCRYPTION_KEY somewhere other than the server itself (a password manager is fine) the moment you generate it. Every record the app stores is encrypted with it — if the server disk is lost and this key wasn't saved elsewhere, the data is gone with it, backups included.
9

Build the app

npm run build

This compiles the production build into .next/. It's normal for this to take a minute or two on a small VPS. On success you'll see a route summary printed at the end with no red error text.

10

Start it with PM2

Create a small PM2 config file so the app always starts the same way, on the right port, from the right folder:

nano ecosystem.config.js
module.exports = {
  apps: [
    {
      name: 'leads-dashboard',
      cwd: '/var/www/leads-erp/leads-dashboard',
      script: 'npm',
      args: 'start -- -p 3000',
      env: {
        NODE_ENV: 'production',
      },
    },
  ],
};

Start it, then tell PM2 to persist across reboots:

pm2 start ecosystem.config.js
pm2 save

pm2 startup
# ^ this prints one command starting with "sudo env PATH=..." — copy that
#   exact line it gives you and run it once. That's what wires PM2 into
#   systemd so the app comes back up automatically after a server reboot.

Verify it's actually up before moving on:

pm2 status
curl -I http://localhost:3000

The curl should return HTTP/1.1 200 OK (or a redirect). If it doesn't, check pm2 logs leads-dashboard before continuing — see the troubleshooting step at the end.

11

Configure Nginx as a reverse proxy

Create a site config that forwards public traffic on port 80 through to the app on localhost:3000:

sudo nano /etc/nginx/sites-available/leads-dashboard
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    # Design Portal uploads (25 MB files, base64-encoded in the request) and
    # encrypted backup restores need real headroom here — the app's own
    # per-field limits are smaller, this is just the outer ceiling.
    client_max_body_size 100M;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

Replace yourdomain.com with your real domain, then enable the site and reload Nginx:

sudo ln -s /etc/nginx/sites-available/leads-dashboard /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl enable nginx

nginx -t tests the config before it's live — if it reports an error, fix that before reloading.

12

Enable free HTTPS (Let's Encrypt)

Only run this once DNS from Step 2 has actually propagated — check with ping yourdomain.com and confirm it resolves to the VPS IP first.

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

Certbot will ask for an email (for renewal/expiry notices) and offer to redirect all HTTP traffic to HTTPS automatically — accept that. It also installs its own renewal timer, so certificates renew themselves; no cron job needed.

Confirm auto-renewal works with a dry run: sudo certbot renew --dry-run
13

Lock the firewall down

Now that Nginx is handling public traffic, open HTTP/HTTPS and make sure nothing external can hit the app's internal port directly:

sudo ufw allow 'Nginx Full'
sudo ufw status

Port 3000 is never opened in the firewall at all — it's only reachable from localhost, which is exactly what the Nginx proxy_pass config needs and nothing more.

14

First login & email setup

Visit https://yourdomain.com — you should land on the sign-in screen. The app seeds a default Super User account on first boot; sign in with that, then immediately go to Settings and change the password.

  • Go to Dashboard → Email Management to configure a real mail provider (Gmail/Outlook relay, a custom SMTP relay, or the built-in Direct Send engine).
  • If you're using Direct Send (no external relay, the app delivers mail itself), follow docs/direct-send-setup-guide.html in this repo for the DNS side — SPF, DKIM, DMARC, PTR, and optionally the BIMI sender logo.
  • Go to Dashboard → Directory to start adding real members — each gets an activation email to set their own password (and optionally their date of birth, for the automated birthday email).
15

Redeploying updates later

Whenever there's new code to ship, from inside leads-erp/leads-dashboard:

cd /var/www/leads-erp/leads-dashboard
git pull origin main
npm install
npm run build
pm2 restart leads-dashboard

pm2 restart is a brief interruption (a few seconds), not a full outage — the process is killed and a fresh one started against the new build. Nginx and your SSL certificate are untouched by any of this.

16

Backups

The app has a built-in encrypted backup/restore tool at Dashboard → Backup — use it to download a full encrypted snapshot on a regular basis and store copies somewhere off the VPS (your own machine, cloud storage, wherever).

At the filesystem level, everything that matters lives in one place:

/var/www/leads-erp/leads-dashboard/data/

This holds every collection (members, events, tasks, ratings, …) as encrypted per-collection JSON files, plus data/uploads/ — the real design files, receipts, and visiting cards those records point to. Back the two up together; the JSON records are meaningless without the files they reference, and vice versa.

None of it is recoverable without DATA_ENCRYPTION_KEY from Step 8. A filesystem backup of data/ without that key saved somewhere is just an encrypted blob forever.

Troubleshooting cheat-sheet

SymptomCheck
Site doesn't load at allsudo systemctl status nginx · sudo nginx -t · sudo ufw status
Nginx loads but shows an error pagepm2 status — is leads-dashboard actually online? · curl -I http://localhost:3000 from the VPS itself
App crashed or won't startpm2 logs leads-dashboard --lines 100 — this shows the real Node.js error
Changes not showing after a deployConfirm npm run build actually finished with no errors before pm2 restart, and that you're editing/pulling inside leads-dashboard, not the repo root
HTTPS certificate errorssudo certbot certificates to check expiry · sudo certbot renew --dry-run to test renewal
Outbound mail not sending (Direct Send)Outbound TCP port 25 is blocked by many hosting providers by default — see docs/direct-send-setup-guide.html, Step 1
Server rebooted and app didn't come backConfirm pm2 startup's printed command was actually run once, and that pm2 save was run after starting the app

Useful commands to keep handy:

pm2 status
pm2 logs leads-dashboard
pm2 restart leads-dashboard
sudo systemctl status nginx
sudo tail -f /var/log/nginx/error.log
