## Overview

The **LEADS Next Gen All-in-One Dashboard & Operations ERP** is a private, role-gated internal enterprise resource planning system built for the LEADS Next Gen Centre at M.S. Ramaiah University of Applied Sciences (MSRUAS), Bengaluru. 

It replaces disparate spreadsheets, WhatsApp groups, and email threads with a unified web portal governing member rosters, event lifecycle, tasks, performance ratings, approvals, digital passes, reimbursements, budget, public forms, and analytics across 7 distinct access tiers.

## Data Flow

1. **Client Request:** User authenticates via session cookie; client sends request with credentials to Next.js API route.
2. **Permission Guard:** Middleware / `member-guard.ts` and `permissions-server.ts` validate tier eligibility, committee membership, or dynamic group policy permissions.
3. **Execution & Mutex Lock:** Handler in `src/app/api` calls `server-db.ts`, acquiring an async mutex for the target collection (e.g., `tasks.json` or `events.json`).
4. **Data Encryption / Decryption:** Sensitive fields (bank accounts, credentials) are processed through `encryption.ts` with AES-256-GCM before writing to disk.
5. **Side-Effects Dispatch:** Asynchronous side effects (such as transactional emails, approval notifications, or audit logs) are enqueued via `email-service.ts` or written to `auditlogs.json`.
6. **Response:** Data is formatted, sanitized via `isomorphic-dompurify` if HTML, and returned to client.

## Technical Debt & Operational Considerations

- [ ] **Horizontal Scaling Bound to Single-Node Disk:** `server-db.ts` uses local file storage (`leads-dashboard/data/*.json`) with in-memory per-process mutexes. Multi-node horizontal scaling requires migrating persistence to PostgreSQL / Supabase or an external database.
- [ ] **In-Process Schedulers:** Schedulers run as long-lived Node.js timeouts/intervals inside Next.js; process restarts (e.g. `pm2 restart`) reset intervals. Migration to an external job queue (Redis / BullMQ / AWS SQS) would improve fault tolerance.
- [ ] **Automated Test Coverage:** Automated unit/integration tests are limited; relies heavily on manual verification scripts in `scripts/` and TypeScript compiler checks.
- [ ] **Local Uploads Directory:** File uploads are saved to local filesystem (`data/uploads`); migrating to S3 or Cloudflare R2 will facilitate automated backups and multi-region durability.

## Conventions

**Naming:**
- Kebab-case for filenames and route paths (`event-passes`, `visiting-card`).
- PascalCase for React components (`DashboardShell`, `EventPassStudio`).
- CamelCase for helper functions and database schema properties (`findApprovalRecipients`, `eventId`).

**Architecture & Access Control:**
- Trust boundaries enforced strictly at server API routes (`permissions-server.ts`), never trusted from client-only checks.
- 7 Role Tiers: Tier 1 (Core Team / Member) through Tier 7 (Super User / SysAdmin).
